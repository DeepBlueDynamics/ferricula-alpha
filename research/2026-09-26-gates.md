## 1. Gate set and type contract

The contract is `ferricula-cognition::gates` (read 2026-09-26, unchanged): every decision
gate returns `Judged<T>` = (`Verdict::Answer(T)` | `Verdict::Abstain(AbstainReason)`) plus
`GateProvenance`. Consumers must not read an abstention as a negative answer.

| Gate | Trait | Verdict type | Backend family (plan §4) | Status today |
|---|---|---|---|---|
| vedanā | `VedanaGate` | `VedanaVerdict { valence, intensity ∈ 0..4, p }` | laya:en (512 tok) | chat backend live; saññā trait absent |
| saññā | *no trait yet* (Dingo §2.4 extension) | six-class distribution | laya:en | research runner only (`research/gates/`) |
| saṅkhāra-merge | `MergeGate` | `MergeVerdict { same_truth, contradiction }` | laya:multilingual (1,024 tok) | chat backend live |
| sati-recall | `SatiRecallGate` | `SatiRecallVerdict { answers_query, relevance ∈ 0..3 }` | laya:en | chat backend live |
| task_succeeded | `TaskSucceededGate` | `TaskSucceededVerdict { p }` | decision (16k tok) | chat backend live |

Invariants enforced by the type system (`gates.rs`, verified by reading, not rerun):

- `Judged::validate` bounds every answer field to its closed range; non-finite → `GateError::OutOfRange`.
- `calibrated == true` without `calibration_sha256` → `CalibratedWithoutHash`.
- `calibrated_answer()` returns `None` unless `calibrated && !state_truncated` — the lifecycle
  cannot consume uncalibrated probabilities through the typed API.
- `AbstainReason`: `NoModel | StateTruncated | LowConfidence { p_max } | ProviderError | NotApplicable | InvalidOutput`.

Measured facts:

**Chosen interim backend (per Eldest Dog: "native Ollaya absence is fine: implement

consumer changes.

## 3. Probability and calibration discipline (hard constraints adopted verbatim)

From Eldest Dog's 22:09Z lane confirmation, incorporated as acceptance rules:

- **Self-reported chat probabilities are not recovered classifier posteriors.** They are the
  model's verbalized distribution over options. This backend never claims calibration from
  applying temperature.
- **Splitting:** calibration and validation sets are externally labelled and
  *source-group-separated* — split by label source family (plan §5.3 splits by
  `source_memory_id`; same principle up one level), never by row.
- **ECE is measured on held-out data only.** Plan §6.3 acceptance: new temperatures accepted
  only if dev ECE improves and accuracy does not drop; this lane tightens to *held-out*
  ECE before the `calibrated` flag may be set.
- **Plan §6.4:** probability-driven lifecycle wiring is prohibited until a gate qualifies
  (dev/held-out ECE < 0.05). `GateBackend.calibration.lifecycle_authorized = false` keeps
  `calibrated = false` regardless of the temperature value (`ferricula-gates` test
  `calibrated_flag_requires_authorization`).
- **Abstention/truncation/provenance are preserved on every row**: each runner record and
  each `Judged<T>` carries timestamp, model, prompt version, latency, token usage,
  `features_sha256`, and raw response. `state_truncated` is always `false` on this backend
  (no 512-token window exists); the field is retained for the Ollaya backend.

Logit recovery and fitting follow plan §6.2 exactly (`z ∝ T·log p`, bounded NLL
minimization over T ∈ [0.05, 20]); implementation in `research/gates/harness/calibrate.py`,
output in plan §6.3 CALIBRATION shape plus an `acceptance` block.

## 4. Abstention policy of the interim backend

| Condition | AbstainReason |
|---|---|
| HTTP/transport error | `ProviderError { message }` |
| No JSON object in completion | `InvalidOutput` |
| Missing class key / out of range / probs sum ∉ [0.95, 1.05] | `InvalidOutput` |
| `p_max < 0.50` (vedanā, 3 classes) / `< 0.34` (saññā, 6 classes) | `LowConfidence { p_max }` |
| Empty text | *not an abstention*: vedanā prompt directs mass to `adukkhamasukha` (boundary row `ven0016`/`vpa0016` exercises this) |

Consumer-side handling stays as cognition specifies: bhāvanā routes merge-abstained clusters
to review; curator keeps retrieval order on recall-gate abstain; `assign_pool` treats
task-outcome abstention as `Pool::Failure` (strict storage rule, outcome.rs).

The SatiMonitor consumes `Valence` from the vedanā gate and `CueSource` from the recall

## 9. Known risks

- *Verbalized probabilities compress toward extremes* (deepseek-v4-pro answered 1.0/0.0 on
  the smoke row). Temperature fitting over `log p` with `p` clipped at 1e-9 is numerically
  stable, but extreme certainty on wrong answers inflates held-out ECE; watch the
  calibration table per model, per language.
- *Cloud model drift*: models are remote and unpinned. `gate_version` carries the exact
  model id; any upstream retirement (cf. deepseek-v4-flash) invalidates comparability —
  rerun baselines on model change.
- *Saññā trait gap*: cognition has no `SannaGate` trait yet (§2.4 is Dingo's extension);
  the research runner measures saññā without the typed contract until then.
