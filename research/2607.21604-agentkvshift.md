# AgentKVShift: Efficient KV Cache Reuse for Agentic Memory Systems

Pandey et al., UC San Diego, arXiv:2607.21604v1 (15 May 2026). <https://arxiv.org/abs/2607.21604>. The PDF is kept locally as `research/2607.21604v1.pdf` (gitignored, not redistributed).

## What it claims
- **The problem:** retrieved agentic memory units (notes with summaries, keywords and tags, or graph nodes) are re-encoded into KV states on every retrieval, and that prefill dominates latency.
  - Training-free KV reuse methods built for RAG (CacheBlend, ProphetKV) lose badly on agentic memory: 47–63% relative F1 at a 10% recompute ratio (A-MEM, Qwen2.5-3B, LoCoMo).
- **The finding:** per memory unit, the KV reuse residual is dominated by one shared offset (the leading singular value drops sharply after mean-centering), plus small token-wise noise.
- **The method:**
  - Recompute a top-b probe set of tokens, chosen by layer-1 deviation.
  - Estimate the per-memory offset per layer from those probes.
  - Add the weighted offset to every non-probe token.
  - It comes with a high-probability bound showing correction beats plain reuse when the common bias exceeds the probe-estimation error.
- **Results:**
  - Within 1.5–6% relative F1 of full recompute at r = 0.1 on LoCoMo (Qwen2.5-3B, Qwen3-4B, Mistral-7B; A-MEM and LiCoMemory).
  - Within about 3% LLM-judge accuracy on AMA-Bench-Recall at r = 0.3 (Qwen3-32B).
  - Prefill speedup of 2–3.5× on an A100.
  - Composes with FP8, KIVI and OTT 2- and 4-bit KV quantization.

## What it means for Ferricula
1. **Not applicable today.** It needs control of the serving engine's KV cache. Steve runs on `glm-5.3:cloud` through Ollama, which exposes no chunk-level KV reuse. It's relevant only if we ever self-host the model with recalled memories as reusable chunks.
2. **It supports the verbatim evidence plane.** The authors note that in note-based memory the metadata (summaries, tags) is what the model attends to. Ferricula keeps sources verbatim and cites them, which is the counterweight to that.
3. **AMA-Bench** (arXiv:2602.22769; Hugging Face dataset `AMA-bench/AMA-bench`) is the useful pointer. It builds memory QA from *agent trajectories* across six domains and four capabilities (Recall, Causal Inference, State Updating, State Abstraction).
   - State Updating maps onto our `supersedes`/`disputes` verdicts.
   - It is added to `docs/BENCH_PLAN.md` as a should-run.
   - It motivates backlog T1: an AMA-Bench-style set built from our own nemesis8 fleet telemetry, with programmatically checkable answer keys.
4. **Their judge protocol** (GPT-4o, binary yes/no, no audit, Appendix A.4) is the kind `docs/BENCH_PLAN.md` warns about. Their absolute scores (LoCoMo F1 about 0.30–0.51 even at full recompute) are the upper bound of *their* pipelines, not a quality bar for ours.
